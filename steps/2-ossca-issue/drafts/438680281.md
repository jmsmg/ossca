제목: [438680281] Check type consistency between pref registration and access

**Bug**

- https://crbug.com/438680281

**Documents**

- `PrefService`는 `SetInt64()`/`GetInt64()`/`SetTime()`/`GetTime()` 접근자에서 "이 pref가 등록될 때 선언한 타입과 지금 접근하는 타입이 같은가"를 `CHECK_EQ`로 검사함(components/prefs/pref_service.cc). 이 검사는 2025-08-28 [CL 6845990](https://crrev.com/c/6845990)에서 이 이슈를 근거로 추가됨
- 새 `CHECK`를 바로 fatal로 켜면 잘못 등록된 pref가 있을 때 크래시가 나므로, 그 CL은 네 곳 모두에 `base::NotFatalUntil::M143` 인자를 붙였음. 이 인자는 지정 마일스톤 전까지 CHECK를 **죽이지 않고 덤프만 남기게** 하는 단계적 롤아웃 장치임
  > [base/check.h:42] An optional base::NotFatalUntil argument can be provided to make the instance
  > non-fatal (dumps without crashing) before a provided milestone. ... Using this lets us probe for
  > would-be CHECK failures for a milestone or two before rolling out a CHECK.
- 판정 로직은 `base/check.cc:69`의 `GetNotFatalUntilSeverity()` — **지정 마일스톤이 현재 마일스톤 이하이면 그냥 `LOGGING_FATAL`**. 현재 `chrome/VERSION`의 MAJOR는 155이고 143 ≤ 155이므로, 이 네 개 CHECK는 **이미 12개 마일스톤째 fatal**이며 인자는 아무 효과 없이 남아 있음
- 정리 방법은 헤더 자신이 지시하고 있음:
  > [base/not_fatal_until.h:14] To clean up old entries remove the already-fatal argument from CHECKs
  > as well as from this list. This generates better-optimized CHECKs in official builds.

**Description**

- 발굴 경로: 코드 상향 — `hunt.py expired components/ net/ services/`로 만료된 `NotFatalUntil` 61곳을 수집한 뒤, **마일스톤 단위로 전 트리를 재집계**해서 "그 마일스톤이 단 한 파일에만 남아 있는" 경우를 찾음. M143이 그중 하나로, 인자 제거와 enum 항목 삭제를 한 CL로 완결할 수 있음
- 착수 전 검증: `bug:438680281` 연결 CL은 원 CL(머지됨)뿐이라 선점 없음 · OSSCA 겹침 0(`NotFatalUntil`·번호 검색 모두 0건) · 이슈는 **NEW·미할당·375일 무활동**
- 수정: 네 곳의 `CHECK_EQ`에서 `, base::NotFatalUntil::M143`만 제거(조건과 `<< path` 스트림은 그대로)하고, `base/not_fatal_until.h`의 enum에서 `M143 = 143,` 한 줄 삭제. +4/−5, 2파일
- **동작 변화**: 크래시 여부는 그대로임(이미 fatal). 달라지는 것은 코드 생성으로, 인자가 없으면 공식 빌드에서 CHECK가 로그 문자열을 버림(`base/check.h:260`). 즉 바이너리가 작아지는 대신 이 CHECK가 터졌을 때 크래시 리포트에 pref 경로가 실리지 않음 — 헤더가 말하는 "better-optimized"의 실체가 이 트레이드오프라 CL 설명에 명시함
- enum 항목 삭제가 안전한 근거: `NotFatalUntil::M143` 참조가 트리 전체에서 이 네 곳뿐이고, `base/check.cc`는 이 enum을 `std::to_underlying`으로 **수치 비교만** 하므로 항목을 열거하거나 switch하지 않음
- 이슈의 본론(모든 pref 접근자에 타입 검사 확대 — `SetTimeDelta`/`GetTimeDelta`에는 아직 검사가 없음)은 남아 있으므로 `Fixed:`가 아닌 **`Bug: 438680281`** 사용
- 한계: `NotFatalUntil`의 취지가 "크래시 리포트를 모아 확신이 서면 fatal로"인데 외부 기여자는 내부 크래시 텔레메트리를 볼 수 없음. 근거는 "12개 마일스톤 동안 되돌리거나 마일스톤을 미룬 흔적이 없다"까지이고, 남겨야 할 이유가 있다면 OWNER의 판단을 따름
- 리뷰어: `components/prefs/OWNERS`는 battre@·gab@ 두 명이고, **gab@**이 원 CL 6845990의 리뷰어이자 `base/` OWNER이기도 해서 두 파일을 한 번에 승인 가능
