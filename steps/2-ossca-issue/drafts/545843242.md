제목: [545843242] PaymentManifestDownloader follows the first manifest Link header instead of requiring exactly one

**Bug**

- https://crbug.com/545843242

**Documents**

- 웹 결제에서 브라우저는 결제 방식 식별자(PMI) URL에 HEAD 요청을 보내고, 응답의 `Link` 헤더에서 `rel="payment-method-manifest"` 링크를 찾아 매니페스트를 내려받음
- [Payment Method Manifest 스펙](https://w3c.github.io/payment-method-manifest/#fetch-pmm)의 "fetch payment method manifest" 알고리즘은 해당 rel을 가진 링크를 **모두 추출한 뒤 그 개수가 1이 아니면 실패**하도록 규정함
  > Let manifest_links be the result of extracting link headers from response whose rel is `payment-method-manifest`.
  > If manifest_links's size is not 1, then return failure.
- 그러나 `PaymentManifestDownloader::OnURLLoaderCompleteInternal()`(components/payments/content/payment_manifest_downloader.cc)은 `SplitLinkHeader()` 루프 안에서 **첫 매칭을 찾자마자** URL을 검증하고 다운로드를 시작한 뒤 `return` 함. 뒤에 매니페스트 링크가 더 있어도 세지 않으므로, 서버가 서로 다른 매니페스트를 가리키는 링크를 여러 개 보내면 브라우저가 임의로 첫 번째를 따라감
- 이미 WPT에 기록된 미해결 동작이었음: `external/wpt/payment-method-manifest/link-header-selection.https.window.js`의 서브테스트 5개 중 "Multiple rel=payment-method-manifest link headers cause fetch to abort" 하나만 실패하며, 그 실패가 `-expected.txt` baseline에 "알려진 실패"로 체크인되어 있었음

**Description**

- 직전 기여 [CL 8336867](https://crrev.com/c/8336867)(crbug 545645933, Link rel 대소문자 매칭)의 쌍둥이 이슈. 같은 함수를 다루므로 그 CL이 머지된 뒤 착수해 충돌을 피함
- 착수 전 Gerrit에서 `bug:545843242`로 연결된 CL이 없음을 확인
- 수정: 루프의 책임을 "수집"으로 좁혀 `std::vector<GURL> manifest_urls`에 모으고, 루프 밖에서 개수를 판정. 0개면 기존 `kNoLinkHeader` 에러, 2개 이상이면 새 에러 `errors::kMultipleLinkHeaders`, 1개면 기존 검증(HTTPS·same-origin)과 다운로드를 그대로 수행
- 개수는 스펙 순서대로 **rel 기준**으로 셈. URL 유효성 검사는 링크가 하나로 확정된 뒤에만 하므로, 유효하지 않은 URL이 섞여 있어도 "여러 개"라는 사실이 먼저 보고됨
- 새 에러 문자열은 `components/payments/core/native_error_strings`의 기존 `kNoLinkHeader` 옆에 추가. 두 에러 모두 `RespondWithError()`가 `$1`을 URL로 치환하는 같은 경로를 사용
- 낡은 WPT baseline은 이 CL에서 함께 삭제. 유일한 `[FAIL]` 항목이 바로 이 버그였으므로 수정 후에는 테스트 전체가 통과하며, baseline을 남겨두면 오히려 불일치로 CQ가 실패함(직전 CL에서 배운 부분을 이번에는 처음부터 반영)
- 검증(TDD): 회귀 테스트 3개를 먼저 작성해 수정 전 실행 → 매니페스트 링크 2개 케이스와 대소문자만 다른 중복 케이스가 **FAILED**(첫 링크로 다운로드가 시작되어 에러 콜백이 오지 않음), 다른 rel 사이에 링크가 하나인 케이스는 통과. 수정 후 새 테스트 3개 통과 및 `*ManifestDownloader*:*PaymentManifestParser*` **140/140 통과**
- 커밋 메시지에 `Fixed: 545843242`를 사용해 머지 시 이슈가 자동 종료되도록 함
