**Documents**

- 웹 결제에서 서버는 매니페스트 위치를 HTTP 응답 헤더로 알릴 수 있음: `Link: <manifest.json>; rel="payment-method-manifest"`
- RFC 8288 section 2.1은 link relation type을 대소문자 구분 없이 비교하도록 규정함
- `PaymentManifestDownloader::OnURLLoaderCompleteInternal()`(components/payments/content/payment_manifest_downloader.cc)은 rel 값을 소문자 리터럴 `"payment-method-manifest"`와 그대로 비교함. 따라서 서버가 `rel="Payment-Method-Manifest"`를 보내면 표준상 유효한 응답인데도 매니페스트 링크가 없는 것으로 처리되어 결제가 실패함
- 원인은 공용 파서에 있음 — `components/link_header_util`는 파라미터 **이름**(`rel=`)만 소문자로 정규화하고(link_header_util.cc:188) **값**은 원문 그대로 넘김. 즉 정규화 책임이 호출자에게 있음

**Description**

- 착수 전 Gerrit에서 `bug:545645933`로 연결된 CL이 없음을 확인
- 수정: rel 값을 relation type으로 분리하기 전에 `base::ToLowerASCII()`로 정규화. 값 전체를 소문자화한 뒤 공백으로 분리하므로 `rel="prefetch PAYMENT-METHOD-MANIFEST"`처럼 여러 relation type이 섞인 경우도 함께 처리됨
- 검증(TDD): 회귀 테스트를 먼저 작성해 수정 전에 실제로 실패하는 것을 확인한 뒤 수정. mixed-case rel 단독 케이스와 다른 relation type과 섞인 케이스 2개를 `payment_manifest_downloader_unittest.cc`에 추가했고, 수정 후 `*ManifestDownloader*` 전체 통과
- 커밋 메시지에 `Fixed: 545645933`을 사용해 머지 시 이슈가 자동 종료되도록 함
- 범위를 좁게 유지하기 위해 유사 이슈 545843242(Link 헤더 개수 검증)는 이 CL에 포함하지 않음
