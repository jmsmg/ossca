| | |
|---|---|
| **입력** | 리뷰 대기 중인 CL ([5단계](../5-commit-and-upload/GUIDE.md)) |
| **출력** | 새 PS + 답글, 최종적으로 CQ+2 / 머지 |
| **완료 조건** | Gerrit CL이 MERGED |
| **다음 단계** | [8단계 — 머지 후 마무리](../8-after-merge/GUIDE.md) |

> ⚠️ **Gerrit 댓글 게시(Send)는 원격 공개다. 사용자 승인 없이 실행하지 않는다.**

---

## 한 라운드의 루프

```
코멘트 해석 → 지적이 맞는지 주변 코드까지 읽고 독립 검증 → 수정
  → 빌드/테스트(tmux, 4단계) → git commit --amend → 새 PS 업로드 → 답글 Send
```

## 답글 규칙

- 반영한 스레드는 **Done** 체크 (자동으로 Resolved 처리) + 상단 Reply에 요약,
  **Send 한 번에 전부 게시**
- 드래프트는 Send 전까지 나만 보인다
- **게시된 댓글은 삭제 불가** (관리자만). 실수로 두 번 올려도 그냥 둔다
- 요청받지 않은 변경을 제안할 땐 **공손한 질문 형식**으로

## Gerrit 메커니즘

- 코드가 바뀐 새 PS가 올라가면 **기존 Code-Review 표는 outdated로 무효화**된다.
  유지되는 copy 조건은 `NO_CHANGE` / `NO_CODE_CHANGE` / `TRIVIAL_REBASE` 등뿐 → 리뷰어가 다시 +1해야 함
- **attention set** = 지금 볼 차례인 사람. 답글을 Send하면 리뷰어로 넘어간다
- CQ가 `REBASE_ALWAYS`라 평소 리베이스는 불필요하지만, Gerrit에 **merge conflict가 표시되면 직접 ToT 리베이스**:
  `git fetch origin && git rebase --autostash origin/main && gclient sync` → 재빌드/재테스트.
  (`--autostash`: gclient가 관리하는 서브모듈 gitlink 수정 수십 건이 워킹트리에 늘 있어 그냥 rebase는 거부됨 — 09-05 8349386에서 확인)
  충돌 해결 시 **업스트림이 헬퍼 시그니처를 바꿨으면 우리 코드도 그 헬퍼로 옮긴다** — 우리 로직을 옛 API 위에 그대로 되살리지 말 것 (8349386: 에러 분리 정책까지 따라감)
  오래 묵힐수록 충돌 위험 증가 (8282239는 5일 만에 충돌)
- 머지는 리뷰어의 **CQ+2**로 들어간다 (컨트리뷰터는 CQ 권한 없음)

## 재촉하기 전에 — 리뷰어의 근무일을 먼저 센다

"며칠째 무응답"을 세기 전에, **그 며칠이 그 사람의 근무일이었는지** 확인한다.

```bash
python3 ~/ossca/scripts/track.py who <리뷰어이메일>
```

그 사람이 리뷰어로 걸린 CL 30건에서 본인 메시지를 모아 **요일·시간 분포**와 마지막 활동 시각을 낸다.
(시간은 PT 기준. 요일 분포는 타임존 오프셋이 몇 시간 달라도 거의 흔들리지 않는다.)

2. **attention set이 이미 그 사람에게 걸려 있으면 ping은 가시성에 아무것도 더하지 않는다** —
   Gerrit 대시보드 맨 위에 이미 떠 있다. 재촉은 근무일이 지났는데도 안 움직일 때만

### 무엇으로 고를 것인가 — 도메인 적합성 vs 가용성

- **기계적·동작 불변 CL**(치환, 만료 인자 제거, include 정리) → **가용성**. 필요한 건 "맞다"는 확인이지 설계 판단이 아니다
- **설계 판단이 필요한 CL**(API 변경, 새 동작) → **도메인 적합성**. 그 파일을 최근 리뷰한 사람을 찾는다

```bash
# 이 파일들을 최근에 «리뷰한» 사람 (작성자가 아니라)
git log origin/main --format=%h -8 -- <파일들> | while read h; do
  git log -1 --format=%B $h | grep -i "^Reviewed-by:"
done | sort | uniq -c | sort -rn
```

## 패치셋만 올리지 말고 답글을 달아라 — attention은 그렇게 돌아온다

2026-09-10, smcgruer@가 8349386 리뷰에서 직접 알려준 것:

> Assuming you are looking to have this re-reviewed, given the new patchset and that you
> re-added Chrome Payments Reviews as a reviewer. In the future, the best way to get your
> reviewers attention back on the change is to:
> 1. **Reply to their comments** (this one, in this case 😊)
> 2. Make sure that the **'attention set' is set to your reviewer**
>    (this happens automatically if you reply to their comments 😊).

**무슨 일이 있었나**: 리뷰 요구사항(feature 게이트·히스토그램)을 구현해 PS3(코드)·PS4(설명)를 올렸는데
**답글을 안 달았다.** 그 결과 `attention_set`이 **비어버려** 리뷰어 대시보드에서 사라졌다.
리뷰어를 다시 추가하는 것으로는 attention이 돌아오지 않는다.

```bash
python3 ~/ossca/scripts/track.py cl <CL>     # "attention: 없음" 이면 아무에게도 안 보이는 상태
```

**규칙**

1. 리뷰 요구를 반영해 새 PS를 올렸으면 **반드시 답글로 무엇을 어떻게 고쳤는지 쓴다.**
   답글이 곧 attention 이동이고, 리뷰어 입장에선 "다시 봐달라"는 신호다
2. 업로드 직후 `track.py cl`로 **attention을 확인**한다. 비어 있으면 답글이 빠진 것이다
3. 리뷰어를 다시 추가하거나 알리아스를 붙이는 것은 attention을 되돌리지 못한다

**미해결 코멘트에 답하는 것도 같은 이유**로 중요하다 — 스레드를 남겨두면 리뷰어가
"아직 대응 중"으로 읽는다.


## 리뷰어가 «더 큰 수정»을 요구할 때 (2026-09-10, CL 8377022)

물러설 지점을 미리 정해두는 건 좋은 습관인데, **한쪽 방향으로만 정해두면 소용이 없다.**

8377022를 낼 때 이렇게 적어뒀다:

> 물러설 지점: 리뷰어가 "다수파대로 최소 수정만"이라고 하면 픽스처 소멸자 한 줄로 되돌린다.

실제로 온 답은 반대였다 — **"테스트 클럭을 쓰지 말고 mock time을 써라."** 더 크고 더 근본적인 정리다.
준비해둔 후퇴선은 아무 쓸모가 없었다.

### 그래서 해야 하는 일

1. **먼저 그 제안이 되는지 직접 조사한다.** 반박도 수용도 조사 다음이다.
   이번엔 조사해보니 리뷰어가 옳았고, 심지어 그가 말한 것보다 더 많이 지울 수 있었다
   (해당 픽스처가 **이미** MOCK_TIME이라 호출 7쌍 중 2쌍은 이미 no-op이었다)
2. **동의하면 동의한다고 먼저 쓴다.** 그리고 조사해서 알아낸 «당신 말이 여기까지 맞다»를 덧붙인다.
   리뷰어는 파일 하나만 보고 말했고, 우리는 전체를 볼 시간이 있었다
3. **판단이 갈리는 지점은 질문으로 남긴다.** ("GetNow()를 호출처 11곳에 인라인할까요, 후속 CL로 둘까요?")
   혼자 정해서 diff를 키우면 리뷰가 한 라운드 더 는다
4. **검증 전에 "고쳤습니다"라고 쓰지 않는다.** "로컬 검증 후 PS2로 올리겠습니다"가 정확하다

### 근본 교훈 — API의 «모양»보다 «필요한가»를 먼저 묻는다

우리는 세터를 `void`로 둘지 `AutoReset` 반환으로 할지를 두고 트리 전체의 관행 분포(558 vs 51)까지 셌다.
그런데 **그 세터가 필요한지**는 묻지 않았다. 호출처가 전부 테스트라는 것까지 확인해놓고도
그 테스트들의 `TaskEnvironment` 설정은 읽지 않았다.

> 테스트 전용 후크(`SetXForTesting`)를 고치기 전에 **그 테스트의 `TaskEnvironment` 선언부터 읽는다.**
> `TimeSource::MOCK_TIME`이 켜져 있으면 `base::Time::Now()`가 이미 mock이므로,
> 클럭 후크는 대개 이미 불필요하다.
