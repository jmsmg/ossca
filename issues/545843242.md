## 현재 코드 (ToT, 8336867 반영 후)

`OnURLLoaderCompleteInternal()` 319~366행: `SplitLinkHeader` 루프 안에서 rel 매칭 → 즉시 URL 검증 →
`InitiateDownload` → **return**. 첫 매칭에서 끝나므로 뒤에 매니페스트 링크가 더 있어도 세지 않음.

## 설계

1. 루프는 **수집만**: rel(소문자화)에 payment-method-manifest가 있으면 `manifest_link_urls.push_back(*link_url)`
   (`ParseLinkHeaderValue` 실패 값은 rel을 알 수 없으니 기존대로 skip)
2. 루프 후 분기: 0개 → 기존 `kNoLinkHeader` / **2개 이상 → 새 에러** / 1개 → 기존 검증(IsValidManifestUrl,
   same-origin)과 `InitiateDownload`를 루프 밖으로 옮겨 그대로 수행
3. 새 상수 `errors::kMultipleLinkHeaders` (native_error_strings, `kNoLinkHeader` 옆):
   `"Multiple \"Link: rel=payment-method-manifest\" HTTP headers found at \"$1\"; exactly one is required."`
4. 스펙대로 **rel 기준으로 개수**를 셈 (URL 유효성은 개수 판정 후 단일 링크에만 적용)
5. 예상 diff: 다운로더 +25/−20(들여쓰기 이동 포함), 에러 문자열 +5, 테스트 +30, baseline −4 → **S~M**

## 테스트 (TDD)

픽스처 `ServerResponse(code, Headers::kSend, link_header, body, net_error)`는 `SetHeader("Link", v)` 한 번 —
실제 HTTP에서 Link 헤더 두 개는 `GetNormalizedHeader`가 쉼표로 합치므로 합쳐진 문자열을 넘기면 동일 상황.
에러 검증은 `EXPECT_CALL(*this, OnManifestDownload(_, kNoContent, "<정확한 메시지>"))` 형식.

1. `MultipleManifestLinkHeadersIsFailure` — `<manifest.json>; rel=payment-method-manifest, <other.json>; rel=payment-method-manifest`
   → 새 에러 메시지로 콜백. **수정 전엔 첫 링크 다운로드가 시작돼 EXPECT_CALL 미충족으로 실패** (빨강 확인용)
2. `MixedCaseDuplicateManifestLinkHeadersIsFailure` — `rel=Payment-Method-Manifest` + `rel=payment-method-manifest`
   → 대소문자만 다른 중복도 2개로 셈 (8336867과 연결)
3. (없으면 추가) `ManifestLinkAmongOtherRelsIsSelected` — `<style.css>; rel=stylesheet, <manifest.json>; rel=payment-method-manifest`
   → 1개로 정상 진행 (WPT "selecting from multiple entries" 대응)
4. WPT baseline `link-header-selection.https.window-expected.txt` 삭제 (유일한 [FAIL]이 이 버그)

## 커밋 메시지 초안

```
[payments] Fail manifest download on multiple manifest Link headers

The payment method manifest spec requires the payment method identifier
response to carry exactly one Link header with
rel="payment-method-manifest": in "fetch payment method manifest", the
extracted manifest links must have a size of 1, otherwise the fetch
fails. PaymentManifestDownloader instead followed the first matching
Link header and ignored any further ones.

Collect the matching Link headers first and fail the download when there
is more than one, then validate and follow the single remaining link as
before. Add regression tests and delete the WPT baseline that recorded
this failure.

Fixed: 545843242
```
