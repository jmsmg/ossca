## 이슈 실체

이슈 제목("BindTime() **and ColumnTime()**")과 본문 모두 읽기·쓰기 양쪽을 범위로 잡았는데, grt의 CL은
**단일행 `BindInt64(N, x.ToInternalValue())` 패턴만** 치환하고 `Fixed:`로 닫았다. 남은 것:

| 종류 | 곳수 | 패턴 |
|---|---|---|
| 읽기 | 23 (등가 22) | `Time::FromInternalValue(ColumnInt64)` · `FromDeltaSinceWindowsEpoch(Microseconds(ColumnInt64))` · `Time() + Microseconds(ColumnInt64)` · TimeDelta 인자로 `Microseconds(ColumnInt64)` |
| 쓰기 | 9 | **다중행** `BindInt64(\n N, x.ToDeltaSinceWindowsEpoch().InMicroseconds())` · `BindInt64(\n N, delta.InMicroseconds())` — grt의 grep이 놓친 형태 |

등가성 (base/time/time.h, sql/statement.cc): `Time::FromInternalValue(us)` = `Time(us)`; `FromDeltaSinceWindowsEpoch(d)` = `Time(d.InMicroseconds())`;
`ColumnTime()` = `FromDeltaSinceWindowsEpoch(Microseconds(int64))`; `ColumnTimeDelta()` = `Microseconds(int64)`. **바이트 동일 → 스키마·마이그레이션 없음.**
제외 1곳: `payments_autofill_table.cc:1493` (`Milliseconds` 직렬화, 다른 단위).

**같은 파일 안에서 이미 비대칭인 곳이 많다** — 이게 CL 설명의 핵심 근거:

- `download_database.cc`: 쓰기 3곳은 `BindTime`(610, 613, 692, 701, 703)인데 읽기 3곳(468, 479, 482)은 `FromInternalValue`
- `keyword_search_term.cc:29` 읽기 `FromInternalValue` ↔ 같은 `last_visit_time` 컬럼을 `url_database.cc:162,192,247`은 `BindTime`으로 씀
- `visit_annotations_database.cc`: 900–901은 `BindTime`, 330/333/412/415는 `BindInt64(.InMicroseconds())`, 456–457은 `Microseconds(ColumnInt64)`
- history 컴포넌트 전체로는 `visit_database.cc`·`url_database.cc`·`history_database.cc`·`visitsegment_database.cc`가 이미 `ColumnTime`/`BindTime`/`ColumnTimeDelta` 전면 사용 → **"history 안에서 남은 4파일만 옛 방식"**
