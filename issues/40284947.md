## 이슈 실체

`net/base/proxy_string_util.h:50`:

```cpp
// TODO(crbug.com/40284947): Remove method once all calls are updated to use
// PacResultElementToProxyChain.
NET_EXPORT ProxyServer
PacResultElementToProxyServer(std::string_view pac_result_element);
```

PAC 문자열(`"PROXY foopy:19"`)을 파싱하는 진입점이 둘인데, 프록시 **체인**(IP Protection의 다중 프록시)을
지원하려고 `ProxyChain` 쪽으로 옮기는 중이다. 이 함수는 그 이전 세대다.

**끝내는 조건은 이미 충족돼 있다** — 프로덕션 호출처가 단 하나이고 그마저 자기 래퍼다:

```
net/base/proxy_string_util.cc:97:  return ProxyChain(PacResultElementToProxyServer(pac_result_element));
```

남은 21곳은 전부 테스트다.

## 착수 전 호출처 추적에서 뒤집힌 것

처음엔 "테스트 호출처를 `PacResultElementToProxyChain`으로 바꾸면 된다"고 봤는데 **틀렸다.**
테스트들은 `ProxyServer` 값 자체가 필요하다:

```cpp
// system_proxy_resolution_service_unittest-inl.h:152
const ProxyServer proxy_server = PacResultElementToProxyServer("HTTPS foopy:8443");
this->resolver()->AddServerToProxyList(proxy_server);   // API가 ProxyServer를 받는다

// client_socket_pool_base_unittest.cc:6009 — 다중 프록시 체인을 조립하는 코드
auto proxy_chain = ProxyChain::ForIpProtection({
    PacResultElementToProxyServer("HTTPS myproxy:70"),
    PacResultElementToProxyServer("HTTPS nonrefreshedproxy:70"),
});
```

체인을 만들려고 **ProxyServer 여러 개**를 넘기는 자리라, 체인 함수로는 애초에 대체가 안 된다.

**대신 net/에 이미 지배적인 관용구가 있다** — 문자열에서 ProxyServer를 만드는 방법 빈도:

| 관용구 | 곳수 |
|---|---|
| `ProxyServer::FromSchemeHostAndPort(scheme, host, port)` | 119 |
| `ProxyUriToProxyServer(uri, scheme)` | 84 |
| **`PacResultElementToProxyServer(pac)`** | **21 (이번에 없앨 것)** |

즉 이 CL은 "PAC 문자열 진입점을 없애고, ProxyServer가 필요한 자리는 이미 다수가 쓰는
`FromSchemeHostAndPort`로 통일"하는 작업이다. TODO의 의도(PAC 문자열은 체인으로만 매핑)와도 맞는다.

   ```cpp
     auto [type, host_and_port] = PacResultElementToSchemeAndHostPort(pac_result_element);
     if (base::EqualsCaseInsensitiveASCII(type, "direct") && host_and_port.empty()) {
       return ProxyChain::Direct();
     }
     return ProxyChain(ProxySchemeHostAndPortToProxyServer(
         GetSchemeFromPacTypeInternal(type), host_and_port));
   }
   ```
